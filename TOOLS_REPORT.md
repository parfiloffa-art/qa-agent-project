# Отчёт по инструментам

## Superpowers

- **Что использовал:** навыки `using-superpowers`, `brainstorming`, `test-driven-development`, `systematic-debugging`, `receiving-code-review`, `requesting-code-review` и `dispatching-parallel-agents`.
- **Что понравилось:** понравился набор навыков для организации работы, планирования и декомпозиции задач. `brainstorming` помогал генерировать идеи для тестов, `test-driven-development` задавал структуру и порядок реализации, а `requesting-code-review` обеспечивал контроль качества через независимую проверку.
- **Что не понравилось:** не понравилось, что расходует достаточно много токенов
- **Что реально помогло:** навыки задали единый порядок работы: сначала проверить инструкции и scope, согласовать дизайн, затем реализовать и прогнать тесты. `systematic-debugging` помог разбирать падения по stack trace и Surefire-отчётам, `receiving-code-review` — корректно декомпозировать перегруженные тест-кейсы, а `dispatching-parallel-agents` — организовать параллельный QA-эксперимент с тремя независимыми направлениями.
- **Буду ли использовать дальше:** да думаю буду, только для задач побольше

## Git worktrees

- **Что использовал:** три отдельных Git worktree для веток `test/term`, `test/validation` и `test/reset`.
- **Что понравилось:** уже ранее пользовался норм
- **Что не понравилось:** внужно больше токенов
- **Что реально помогло:** позволили независимо реализовать три UI-автотеста, не смешивать изменения между задачами и затем объединить готовые ветки в `main`. Разделение также упростило проверку scope каждого коммита.
- **Буду ли использовать дальше:** если будет подписка x5 клода либо гпт, при прошке нет смысла

## Subagents

- **Что использовал:** три параллельных субагента: Formats Agent, Boundaries Agent и States Agent; основной агент выступал координатором, сохранял исходные ответы, проверял traceability и объединял результат.
- **Что понравилось:** понравился сам опыт, можно делать больше более объемной работы за более короткий срок
- **Что не понравилось:** в целом все хорошо но чтобы пользоваться такой фичей нужно очень очень много токенов иначе нет смысла
- **Что реально помогло:** независимое разделение анализа поля процентной ставки дало 32 сырых сценария по форматам, границам и состояниям. После повторной проверки и удаления двух реальных дублей получен набор из 30 уникальных сценариев и 10 зафиксированных неоднозначностей требований.
- **Буду ли использовать дальше:** если будет подписка x5 клода либо гпт, при прошке нет смысла

## Sandbox

- **Что использовал:** файловую изоляцию workspace, контролируемое повышение разрешений для точечных операций и отдельный эксперимент записи внутри и вне разрешённой области.
- **Что понравилось:** Удобно изолировать агентов и контролировать доступ к файловой системе, особенно при работе с Git worktree и локальным сервером.
- **Что не понравилось:** нет минусов
- **Что реально помогло:** sandbox сохранил изменения внутри проекта и заблокировал создание файла вне workspace с `operation not permitted`. Контроль разрешений также сделал явными операции, которым требовался доступ к порту локального сервера или Git-индексу linked worktree.
- **Буду ли использовать дальше:** да, уже много раз использовал и до домашки 

## Codex

- **Что использовал:** основной AI-агент для анализа требований, подготовки тестовой документации, реализации Java UI-автотестов, диагностики падений, ведения журналов сессий и обновления проектного отчёта.
- **Что понравилось:** Все нравится
- **Что не понравилось:** лимиты
- **Что реально помогло:** связал требования из `SPEC.md` со scope из `TEST_PLAN.md`, подготовил тест-кейсы и workflow, реализовал четыре автоматизированных сценария, провёл breaker-анализ и сохранил воспроизводимые артефакты в `sessions/`, `runs/` и отчётах.
- **Буду ли использовать дальше:** конечно

## In-app Browser

- **Что использовал:** навык `browser:control-in-app-browser` для управления локальной страницей, ввода данных, переключения элементов, перезагрузки и проверки viewport 360 и 1440 px.
- **Что понравилось:** все
- **Что не понравилось:** нет минусов
- **Что реально помогло:** позволил проверить реальное состояние UI до написания smoke-набора и выполнить 17 независимых breaker-попыток. Через браузер подтверждены расчёты, валидация, график, reset/reload, адаптивность и воспроизведён дефект длинного цифрового ввода.
- **Буду ли использовать дальше:** да

## Playwright

- **Что использовал:** Playwright for Java для взаимодействия с реальной страницей через стабильные HTML `id` и видимые `label`, ожиданий UI-состояний и проверок текста, атрибутов и видимости элементов.
- **Что понравилось:** все 
- **Что не понравилось:** нет минусов 
- **Что реально помогло:** на нём реализованы `TC-CALC-001`, `TC-TERM-001`, `TC-VAL-001` и `TC-RESET-001`. Реальные browser-действия обнаружили ошибки самих тестов при попытке `check()` скрытых radio и помогли заменить их на пользовательский клик по видимому `label`.
- **Буду ли использовать дальше:** да, с ним и работаю

## Java и JUnit 5

- **Что использовал:** Java с target release 17 и JUnit 5 для структуры тестовых классов, lifecycle-методов, assertions и независимых test cases.
- **Что понравилось:** скорость
- **Что не понравилось:** нет минусов
- **Что реально помогло:** позволили оформить каждый согласованный сценарий отдельным самодостаточным классом, автоматически поднимать и останавливать окружение и точно фиксировать причины падений. Итоговый suite содержит четыре независимых теста.

## Maven и Surefire

- **Что использовал:** Maven для сборки и запуска узких и полных прогонов; Maven Surefire для отчётов, stack trace и итоговой статистики.
- **Что понравилось:** скорость сборки и запуска
- **Что не понравилось:** нет минусов
- **Что реально помогло:** команды вида `mvn test -Dtest=...` ускоряли локальную диагностику одного класса, а полный `mvn test` подтверждал отсутствие регрессии. Surefire помог установить причины timeout, различий `innerText()`/`hasText()` и первоначального предупреждения о потоке forked JVM.
- **Буду ли использовать дальше:** да
