# Сценарии по состояниям поля ставки

1. `RATE-01` — Нетронутое пустое поле ставки в начальном состоянии  
Проверяемое требование: `Пустые обязательные поля не показывают ошибку в начальном состоянии`; состояние `Начальное`; `Отдельной кнопки «Рассчитать» нет`.  
Предусловия: страница калькулятора открыта впервые или после перезагрузки; сумма, ставка и срок пустые; тип платежей — аннуитетный по умолчанию.  
Тестовые данные: не требуются.  
Краткие шаги: не взаимодействовать с полем ставки.  
Точный ожидаемый результат: поле ставки пустое; под полем ставки нет сообщения об ошибке; поле не подсвечено как ошибочное; подробный результат и сравнительный блок не показаны; отдельной кнопки `Рассчитать` нет.

2. `RATE-02` — Пустое поле ставки после потери фокуса  
Проверяемое требование: `Сообщение «Заполните поле» появляется только у поля, с которым пользователь уже взаимодействовал: оставил его пустым после потери фокуса`; при неполных данных результат скрыт.  
Предусловия: открыто начальное состояние калькулятора.  
Тестовые данные: пустое значение ставки.  
Краткие шаги: поставить фокус в поле ставки; не вводить значение; убрать фокус из поля.  
Точный ожидаемый результат: под полем ставки показано сообщение `Заполните поле`; сообщение показано текстом, а не только цветом; подробный результат и сравнительный блок не показаны.

3. `RATE-03` — Очистка ранее заполненного поля ставки  
Проверяемое требование: `Сообщение «Заполните поле» появляется ... если пользователь очистил ранее введённое значение`; `Пустое обязательное значение немедленно скрывает все устаревшие результаты`.  
Предусловия: в поле суммы введено `100000`; в поле срока введено `12` месяцев; в поле ставки введено валидное значение; подробный результат и сравнительный блок уже показаны.  
Тестовые данные: было `12`, становится пусто.  
Краткие шаги: выделить содержимое поля ставки; удалить значение.  
Точный ожидаемый результат: поле ставки становится пустым; под ним показано сообщение `Заполните поле`; ранее показанные подробный результат и сравнительный блок немедленно скрыты; отдельного действия для скрытия результата не требуется.

4. `RATE-04` — Ввод валидного значения ставки  
Проверяемое требование: `Как только все значения становятся корректными, калькулятор без отдельной кнопки показывает подробный результат`; `Корректное изменение любого параметра немедленно обновляет подробный результат и сравнение`.  
Предусловия: сумма `100000` и срок `12` месяцев уже введены корректно; поле ставки пустое; подробный результат и сравнительный блок не показаны.  
Тестовые данные: ставка `12`.  
Краткие шаги: ввести в поле ставки `12`.  
Точный ожидаемый результат: под полем ставки нет ошибки; подробный результат показан автоматически; сравнительный блок показан автоматически; отдельная кнопка `Рассчитать` не появляется и не требуется.

5. `RATE-05` — Замена валидного значения ставки на невалидное  
Проверяемое требование: `Ошибки показываются сразу под соответствующим полем после появления некорректного значения`; `Некорректное ... значение немедленно скрывает все устаревшие результаты`.  
Предусловия: сумма `100000`, срок `12` месяцев и ставка введены корректно; подробный результат и сравнительный блок показаны.  
Тестовые данные: было `12`, становится `12,345`.  
Краткие шаги: заменить валидное значение ставки `12` на `12,345`.  
Точный ожидаемый результат: под полем ставки сразу показано текстовое сообщение валидации, объясняющее допустимый формат или диапазон ставки; подробный результат и сравнительный блок скрыты; устаревшие результаты не остаются на экране.

6. `RATE-06` — Немедленное скрытие устаревшего результата при инвалидизации ставки  
Проверяемое требование: `Некорректное или пустое обязательное значение немедленно скрывает все устаревшие результаты`.  
Предусловия: сумма `100000`, срок `12` месяцев и ставка введены корректно; подробный результат и сравнительный блок показаны; фокус находится в поле ставки.  
Тестовые данные: `12,34` → `12,345`.  
Краткие шаги: допечатать в валидное значение ставки третий знак после разделителя, чтобы получить `12,345`; не уводить фокус из поля.  
Точный ожидаемый результат: в момент, когда значение становится невалидным, подробный результат и сравнительный блок скрываются сразу, без потери фокуса и без дополнительного действия пользователя; под полем ставки показано текстовое сообщение валидации.

7. `RATE-07` — Исправление последней ошибки в поле ставки  
Проверяемое требование: `После исправления последней ошибки результаты появляются автоматически`; ошибка должна исчезнуть после возврата к корректному значению.  
Предусловия: сумма `100000` и срок `12` месяцев корректны; поле ставки содержит невалидное значение; под ним показана ошибка; подробный результат и сравнительный блок скрыты.  
Тестовые данные: `12,345` → `12,34`.  
Краткие шаги: исправить значение ставки с `12,345` на `12,34`.  
Точный ожидаемый результат: сообщение валидации под полем ставки исчезает после того, как значение снова становится валидным; поле больше не находится в ошибочном состоянии.

8. `RATE-08` — Автоматическое восстановление результата после исправления ставки  
Проверяемое требование: `После исправления последней ошибки результаты появляются автоматически`; `Корректное изменение любого параметра немедленно обновляет подробный результат и сравнение`.  
Предусловия: сумма `100000` и срок `12` месяцев корректны; ставка невалидна; под полем ставки показана ошибка; подробный результат и сравнительный блок скрыты.  
Тестовые данные: `12,345` → `12,34`.  
Краткие шаги: исправить значение ставки до валидного `12,34`; не нажимать никаких кнопок и не запускать отдельный расчёт.  
Точный ожидаемый результат: подробный результат и сравнительный блок появляются автоматически сразу после исправления последней ошибки; отдельная кнопка `Рассчитать` не требуется и не появляется.

9. `RATE-09` — Отсутствие отдельной кнопки расчёта для поля ставки  
Проверяемое требование: `Отдельной кнопки «Рассчитать» нет`; `При корректном заполнении всех полей результаты появляются без нажатия отдельной кнопки`.  
Предусловия: открыто начальное состояние калькулятора.  
Тестовые данные: сумма `100000`, срок `12` месяцев, ставка `12`.  
Краткие шаги: проверить интерфейс до ввода; затем ввести корректные сумму, срок и ставку.  
Точный ожидаемый результат: в интерфейсе отсутствует отдельная кнопка `Рассчитать` как до ввода, так и после него; после ввода валидной ставки при уже корректных сумме и сроке подробный результат и сравнительный блок появляются автоматически.

## Итог

Количество сценариев: `9`.

Использованные тестовые данные: `100000` ₽, `12` месяцев, аннуитетный тип платежей по умолчанию, ставки `12`, `12,34`, `12,345`, пустое значение.

Найденные неоднозначности:
- Для невалидной непустой ставки спецификация требует текстовое сообщение, объясняющее формат или диапазон, но не фиксирует точную формулировку текста.
- Слово `немедленно` задаёт поведение по сути, но не задаёт технический критерий времени показа/скрытия; для теста разумно трактовать это как обновление без потери фокуса и без отдельного действия пользователя.

Возможные дубли внутри результата:
- `RATE-05` и `RATE-06` частично пересекаются: оба проверяют переход из валидной ставки в невалидную, но `RATE-05` фокусируется на состоянии ошибки, а `RATE-06` — именно на моментальном скрытии устаревшего результата.
- `RATE-07` и `RATE-08` частично пересекаются: оба используют исправление последней ошибки, но `RATE-07` фокусируется на снятии ошибки у поля, а `RATE-08` — на автоматическом восстановлении результата без отдельного действия.
