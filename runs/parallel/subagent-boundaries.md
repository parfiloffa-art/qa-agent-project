# Граничные сценарии по полю «Годовая процентная ставка»

Общая фикстура для всех сценариев:

- сумма кредита: `100000`
- срок: `12` месяцев
- тип платежей: `аннуитетный`
- меняется только поле ставки
- вне scope: проверка остальных полей, графика, адаптивности и конкретных денежных сумм

## Сценарии

### RATE-BND-01 — Минимальная граница `0,01%` принимается
- Проверяемое требование: ставка допускается в диапазоне от `0,01%` до `133%` включительно.
- Предусловия: открыта страница калькулятора; введены `100000` в поле суммы и `12` в поле срока; выбран аннуитетный тип платежей; поле ставки пустое.
- Тестовые данные: ставка `0.01`
- Краткие шаги:
  1. Ввести в поле ставки `0.01`.
  2. Увести фокус из поля.
- Точный ожидаемый результат: поле ставки считается валидным; сообщение об ошибке под полем ставки отсутствует; подробный блок результата и сравнительный блок автоматически отображаются.

## Итог

- Количество сценариев: `10`
- Использованные тестовые данные по ставке: `0.00`, `0.01`, `0.02`, `12`, `12.5`, `12.34`, `12.345`, `132.99`, `133`, `133.01`

## Найденные неоднозначности

- В спецификации не задан точный текст ошибок для нарушения диапазона и для превышения количества знаков после разделителя, поэтому в expected result можно жёстко проверять смысл сообщения, но не конкретную формулировку.
- Формулировка “значения непосредственно внутри/за границами” не уточняет шаг, но из ограничения “не более двух знаков после разделителя” логично следует шаг `0,01` для ставок с дробной частью.

## Возможные дубли внутри результата

- `RATE-FMT-07` частично пересекается с `RATE-BND-04`, потому что `133` одновременно является и граничным, и валидным целым значением. Сценарий оставлен, чтобы изолировать правило “0 знаков после разделителя”.
- `RATE-FMT-09` частично пересекается с `RATE-BND-01`, `RATE-BND-02` и `RATE-BND-05`, потому что те тоже используют 2 знака после разделителя. Сценарий оставлен, чтобы отдельно проверить правило формата без привязки к границе.
