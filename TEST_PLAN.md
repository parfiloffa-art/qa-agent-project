# Тест-план кредитного калькулятора «Банк Прикола»

## Объект тестирования

Локальное web-приложение — кредитный калькулятор «Банк Прикола».

Основной источник требований: `SPEC.md`.

## Цель

Проверить соответствие реализации требованиям `SPEC.md`, выявить функциональные и
UI-дефекты и автоматизировать основные регрессионные пользовательские сценарии.

## Scope

- начальное состояние калькулятора;
- ввод суммы кредита;
- валидация процентной ставки;
- ввод срока кредита;
- переключение месяцев / лет;
- выбор типа платежей;
- аннуитетный расчёт;
- дифференцированный расчёт;
- сравнение схем;
- график платежей;
- автоматический пересчёт;
- обработка невалидных значений;
- сброс;
- адаптивность.

## Out of scope

Не тестируются:

- оформление заявки на кредит;
- backend и API;
- авторизация;
- база данных;
- комиссии и страховки;
- досрочное погашение;
- изменение ставки во время срока;
- ПСК;
- аннуитетный помесячный график;
- экспорт данных;
- сохранение параметров между сессиями.

## Виды тестирования

- функциональное;
- расчётное;
- UI testing;
- responsive testing;
- regression testing.

## Подходы и техники тест-дизайна

- позитивное тестирование;
- негативное тестирование;
- boundary testing;
- validation testing;
- state transition testing.

## Тестовые данные

Используются:

- классы эквивалентности;
- граничные значения;
- значения непосредственно ниже и выше границ;
- валидные типовые значения;
- невалидные форматы;
- контрольные расчётные примеры из `SPEC.md`.

## Тестовое окружение

Приложение запускается локально:

```bash
python3 -m http.server 8765
```

URL:

[http://localhost:8765](http://localhost:8765)

Браузер:

- Chrome.

Целевые ширины viewport:

- 360 px;
- 1440 px.

## Automation scope

Автоматизируются:

- основные positive flows;
- граничные значения;
- validation;
- автоматический пересчёт;
- переключение типа платежей;
- переключение месяцев / лет;
- контрольный расчёт;
- сброс;
- основные состояния графика;
- responsive-проверки.

Стек:

- Java;
- Playwright;
- JUnit 5;
- Maven.

## Риски и ограничения

- ошибки округления могут проявляться только на отдельных наборах данных;
- большой срок кредита создаёт длинный график платежей;
- часть визуальных требований требует отдельной проверки на разных viewport;
- автоматизированные проверки не заменяют полностью визуальную оценку интерфейса.

## Definition of Done

Тестирование считается завершённым, когда:

- требования из `SPEC.md` соблюдены;
- выбранный набор тест-кейсов автоматизирован;
- автотесты успешно запускаются одной командой;
- результаты тестовых прогонов сохранены в `runs/`.
