# Кредитный калькулятор «Банк Прикола»

Учебный проект: одностраничный кредитный калькулятор и комплект QA-артефактов, подготовленных в рамках домашней работы по agentic workflow. Цель — реализовать приложение по [`SPEC.md`](./SPEC.md), спланировать и выполнить его проверку, автоматизировать часть smoke-набора и зафиксировать воспроизводимый процесс, эксперименты и ограничения.

Проект выполнен **индивидуально автором, без участия команды**. AI-агенты применялись как рабочие инструменты и специализированные роли внутри личного workflow, но не являлись членами команды или соавторами.

Калькулятор поддерживает аннуитетную и дифференцированную схемы, автоматически пересчитывает и сравнивает результаты, валидирует сумму, ставку и срок, показывает график дифференцированных платежей и адаптируется к размеру экрана.

## Быстрый запуск

Для работы приложения нужен Python 3. В корне репозитория выполните:

```bash
python3 -m http.server 8765
```

Затем откройте [http://localhost:8765](http://localhost:8765). Для запуска самого приложения установка зависимостей и доступ к интернету не требуются.

## Автотесты

Для полного прогона нужны:

- JDK 17 или новее;
- Maven;
- Python 3;
- установленный Google Chrome;
- свободный порт `8765`.

Из корня репозитория выполните:

```bash
mvn test
```

Тесты сами запускают локальный сервер на `127.0.0.1:8765`, если приложение ещё недоступно, и открывают системный Chrome в headless-режиме. При первом запуске Maven может потребоваться доступ к настроенному репозиторию зависимостей.

Автоматизированы четыре утверждённых smoke-кейса: `TC-CALC-001`, `TC-TERM-001`, `TC-VAL-001` и `TC-RESET-001`. Это `4` из `18` кейсов в [`TEST_CASES.md`](./TEST_CASES.md); остальные не следует считать автоматизированными. Сохранённый полный прогон: [`runs/2026-08-27-full-suite.md`](./runs/2026-08-27-full-suite.md) — 4 теста, 0 failures, 0 errors, 0 skipped.

## AI-агенты и организация работы

Вся проектная работа выполнялась автором самостоятельно. Основной Codex-агент использовался для анализа, реализации, автоматизации, запусков и документации. В parallel-эксперименте работали три специализированных QA-субагента — Formats Agent, Boundaries Agent и States Agent. Breaker Agent был отдельной проверочной ролью основного агента, а read-only reviewer-субагент проверял итоговый отчёт и методологию поиска секретов.

Автоматизация `TC-TERM-001`, `TC-VAL-001` и `TC-RESET-001` создавалась в трёх отдельных Git worktree; затем результаты были объединены в основную ветку. Подробные prompts, принятые и отклонённые результаты находятся в [`sessions/`](./sessions/), а выводы и фактические замеры — в [`REPORT.md`](./REPORT.md).

## Известные ограничения

- Автоматизированы 4 из 18 smoke-кейсов; полный перечень непокрытых сценариев и рекомендаций приведён в профильных отчётах.
- Breaker-анализ выявил один незакрытый дефект Low: очень длинные цифровые значения классифицируются как ошибка формата, а не диапазона; расчёт при этом блокируется безопасно.
